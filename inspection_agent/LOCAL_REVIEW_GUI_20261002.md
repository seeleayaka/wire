# 局部复核导入：正式GUI入口

原DINO复核界面新增“导入局部复核记录（不确认故障）”按钮及摘要。工单等待人工复核时启用，检测运行时禁止导入；原人工差异确认、修改建议和复检控件不改含义。

先完成当前照片的视觉分析，再点击导入并选择一个JSON导入清单，格式：

```json
{"schema_version":1,"bundle":"bundle.json","review":"review.json","evidence_files":"evidence_files.json","plan":null}
```

所有相对路径以该清单目录解析。bundle是页面构建时的元数据，review是保存的V1/V2局部意见；evidence_files指向后端来源清单（每个case的map/endpoints/audit）。plan可填预期表草稿路径或null。清单本身不携带审核结论，不能更改记录类型。

当前参考/待检图片路径必须与工单一致。依据当前待检照片的路径/SHA/尺寸/坐标系自动唯一匹配case，不让人凭相似名称选视角。工单在选文件期间更换或变化时拒绝，来源核验仍由已测试后端执行。测试记录默认拒绝，GUI不提供绕过开关。

导入摘要显示支持、排除、无法确认和未处理数量。局部意见不是故障确认，预期表仍未确认；状态仍awaiting_human_review，不启动拓扑比较或维修建议。已有局部意见会在状态更新时显示保存数量。

8项新增实际Qt按钮/桥接测试、旧21项工单/GUI/后端回归通过。Qt截图和合成操作员格式夹具的保存重载检查通过；夹具只是测试，不是真实操作员意见，不是新视觉推理或全链精度验收。

当前证据包仍仅覆盖两张固定照片，其他输入会安全拒绝；尚无从每次视觉分析动态生成证据包的通用入口。下一步先完成现有机箱主场景的完整检测、人工确认、复检评价，机柜拓扑保留受限扩展。
