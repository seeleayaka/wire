线缆柜装配模板与规则引擎实施计划
日期：2026-08-19
状态：待实施

一、已确认的第一版范围

1. 产品范围：只服务当前这一个线缆柜柜型（不做多产品/多模板选择界面）。
2. 建模方式：全自动；不要求操作员首次手动框选、确认候选或为接口编号。
3. 首批检测目标：漏装、颜色错误、安装位置偏位。
4. 暂不作为第一版正式结论：完整线缆路径追踪、端子 A 接到端子 B 的接错判定、背面或遮挡关系、电气连通性。
5. 结果边界：单张图片自动生成的规则属于视觉推断。证据不足时输出“待复核”，不得把不确定的视觉结果硬判为 NG。

二、目标架构

标准样例图
  -> Reference Builder（自动生成候选结构）
  -> 当前柜型 AssemblyTemplate.json
  -> 生产图 + 现有整机 SIFT/MAGSAC 对齐
  -> Vision Observation（读取实际位置、颜色、存在性）
  -> Rule Engine（标准模板与实际观察比较）
  -> OK / 疑似 NG / 待复核，并列出原因和证据框

现有 DINO + 传统差异检测继续保留，但角色调整为“异常证据提供者”：
- DINO 框不能单独形成 NG；
- 模板规则与 DINO/传统差异相互印证，才提高疑似 NG 置信度；
- 整柜边缘、标签、反光等无模板对象支撑的变化，降为待复核或忽略。

三、数据文件设计

新增文件：config/current_cabinet_assembly_template.json

建议初始结构：
{
  "schema_version": 1,
  "template_id": "current_cable_cabinet_v1",
  "reference_image": ".../right.png",
  "image_size": [1080, 712],
  "build_mode": "automatic_single_reference",
  "objects": [
    {
      "id": "wire_001",
      "kind": "wire_candidate",
      "color": {"name": "yellow", "bgr": [0, 210, 230], "tolerance": 48},
      "center_norm": [0.42, 0.38],
      "direction_deg": 35,
      "expected_region": [0.38, 0.32, 0.47, 0.45],
      "presence_threshold": 0.60,
      "position_tolerance_px": 15,
      "confidence": "automatic_candidate"
    }
  ],
  "rules": [
    {
      "id": "wire_001_presence",
      "type": "exists",
      "object_id": "wire_001",
      "severity": "suspected_ng"
    }
  ]
}

说明：坐标均用标准图归一化坐标保存；生产图必须先配准回标准图坐标系。第一版不把自动候选伪装成已知物料编号；object id 仅是稳定的内部编号。

四、实施步骤与交付物

阶段 0：先处理当前整柜噪声（前置）
- 给配准结果增加有效 warp 区域，屏蔽转换后无效边缘。
- 将 DINO/传统差异从“任一高即可框”调整为“跨证据支持才形成整柜候选”。
- 以 wrong1~wrong5、memory2 及 right 为回归集；要求保留 memory2 的真实小异常，减少 wrong4 的右侧边缘、导轨和标签框。
- 交付：噪声修复、回归报告、修改前后候选框对比。

阶段 1：模板数据模型与读写（最小可运行基础）
- 新增 assembly_template.py：数据校验、归一化坐标转换、JSON 加载与保存。
- 建立 current_cabinet_assembly_template.json；现有 template_review_recipe.json 保持兼容且不覆盖。
- 明确 schema_version，给未来多柜型和人工确认预留字段，但不做对应 UI。
- 交付：可从命令行加载、校验并打印模板摘要的脚本与单元/烟雾测试。

阶段 2：Reference Builder（标准图自动候选提取）
- 输入：当前标准 right.png。
- 候选 1：检测可见线材片段：颜色聚类 + 边缘/细长形态 + 局部方向；保存颜色、中心、方向、候选区域和置信度。
- 候选 2：检测端子/接口邻域：基于重复排列、矩形/端子排结构和线端邻近关系，自动编号 C001、C002……；仅作未来拓扑扩展的数据，不在第一版承诺接线判断。
- 候选 3：卡扣/显著小部件：仅在候选质量足够时记录；不强迫生成。
- 自动过滤：柜门边缘、导轨边界、文字标签和大面积背景不得成为“装配件规则”。
- 交付：标准图运行后生成模板 JSON、候选可视化图、build_report.json（含每个候选的置信度与被过滤原因）。

阶段 3：Vision Observation（生产图实际观察）
- 复用现有 SIFT/MAGSAC 全机对齐；定位不可靠时直接“待复核”，不做规则判断。
- 在每个模板对象的 expected_region 内重新提取线材颜色、细线结构、中心和方向。
- 生成 actual_observations，不覆盖标准模板；每个观察都含 evidence：颜色相似度、结构存在度、DINO 差异、传统差异、坐标误差。
- 交付：对 right/wrong 系列输出 observation_report.json 和叠加证据图。

阶段 4：Rule Engine（第一版）
- exists：标准对象存在、实际不存在 -> “疑似漏装”。
- color：存在但颜色距离超过容差 -> “疑似错色”。
- position：中心点或方向超过容差 -> “疑似偏位”。
- 判定等级：
  * OK：对象证据充足且所有已启用规则通过；
  * suspected_ng：至少一条规则失败，且有结构/颜色/差异中的多项证据；
  * manual_review：定位或对象识别证据不足、规则互相矛盾；
  * no_conclusion：模板尚未产出足够可靠的自动候选。
- 输出必须含“标准值、实际值、证据、置信度、对应图框”，便于原型演示。
- 交付：assembly_rule_engine.py、机器可读 report.json、可读中文结论。

阶段 5：接入现有 UI（最后做）
- 现有“选择标准图/生产图/运行”流程不变。
- 增加“自动生成当前柜型模板”和“按装配规则检测”按钮；不增加手动框选步骤。
- 结果页同时显示：配准质量、规则结论、异常类型、证据框；DINO 热图保留在诊断页。
- 若未找到可用模板，明确提示“模板候选不足，当前只运行差异复核”，不静默给 OK。

五、验收与回归标准

必测图片：right、wrong1~wrong5、memory2 的现有正常/异常对。

1. 所有图先经过定位可靠性门槛；不能可靠对齐时不输出装配 OK/NG。
2. 当前已知真实差异至少仍被报出为 suspected_ng 或 manual_review，不能因降噪被吞掉。
3. 整柜右边缘、导轨、标签等已知噪声不应成为独立的“线材漏装/错色/偏位”结论。
4. 标准图自身生成模板后，再对标准图检测，应为 OK 或 no_conclusion，不能产生疑似 NG。
5. 每次修改同时运行回归脚本，并保存 report 供比较。

六、后续扩展（不纳入第一版）

- 接线拓扑：基于自动接口候选和线端走廊，生成 C001 -> C00N 的图结构，做图匹配。
- 多张合格图：用多个正常样本建立颜色/位置容差，显著降低单样例偏差。
- 可选模型：接入线材/端子姿态模型，作为 Vision Observation 的可替换实现；LightGlue 只作对齐备用方案。
- 实时相机引导：先用柜体轮廓、清晰度、角度门控获得绿色可拍画面，再调用上述模板检测。
